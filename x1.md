# 0. CRITICAL CONTEXT

TrimAURA is a mobile-first PWA for turning long-form video into short vertical clips.

The production pipeline is approximately:

Phone/Desktop PWA
→ FastAPI
→ job creation
→ Modal worker
→ download
→ transcription
→ AI analysis
→ clip selection
→ silence trimming
→ face detection/tracking
→ vertical rendering
→ captions/templates
→ Modal Volume / storage
→ API
→ PWA polling
→ clip viewer
→ actual phone playback/download

The primary observed problem is:

> Jobs tend to work reliably when tested from IDE/local development, but intermittently fail, get stuck, disappear, or appear unsuccessful when used from the physical phone PWA.

The backend pipeline itself is not intentionally different between the environments.

We therefore need to isolate whether the problem is:

A. PWA/frontend lifecycle/polling/service-worker behavior

B. Upload transport / mobile network behavior

C. Backend pipeline/video characteristics

D. Storage/retrieval/playback

E. Modal/cloud/environment issues

F. Route-parity/configuration issues

G. An interaction between several of the above

# 4. TEST DEFINITION

A job is NOT considered successful merely because:

- API returned 200
- Job row exists
- Job status says COMPLETED
- Modal function finished
- clips exist somewhere

A job is only considered **USER-SUCCESSFUL** if:

1. Job can be submitted from the client.
2. Job appears correctly.
3. Backend processes it.
4. Correct terminal state reaches the client.
5. Generated clips appear in the PWA.
6. Clip opens.
7. Actual MP4 is valid.
8. Phone can play it.
9. Seeking works.
10. Download works.
11. Downloaded file is valid.
12. Settings requested by the user actually affected output.

This is the primary reliability metric.
